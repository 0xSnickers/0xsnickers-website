# 如何让 Codex 连接Ubuntu 服务器

这篇记录的是我实际配置 **Codex App 通过 SSH 连接Ubuntu** 的过程。我的 Ubuntu 跑在 VMware 里，但这套方法不只适用于 VMware：只要你的 Mac 能通过 SSH 连到那台 Ubuntu，就可以让 Codex 在远端文件系统和远端 shell 里工作。

我这里中间加了一层 **Tailscale**，主要是为了拿到一个稳定的内网地址。这样无论 VMware 的 NAT IP 怎么变、Mac 和 Ubuntu 是否在同一个局域网，Codex 都可以继续通过同一个 SSH Host 连接到 Ubuntu。

最终目标是：

- **Mac** 只作为操作入口，负责使用 Codex App、审批操作、查看 diff 和运行结果。
- **Tailscale** 提供稳定的内网地址，让 SSH 不依赖 VMware 当前分配的局域网 IP。
- **Ubuntu** 存放项目代码和开发依赖，真正执行 `npm install`、`npm run build`、测试、Git 等命令。
- **Codex App** 读取 Mac 的 `~/.ssh/config`，发现 SSH Host，然后在 Ubuntu 的项目目录中创建远程项目。

这张图里最重要的是四个边界：

- **Codex App 不直接运行你的项目**：它在 Mac 上负责交互，但实际命令会通过 SSH 进入 Ubuntu 执行。
- **Tailscale 只解决网络可达性**：它提供稳定的 `100.x` 地址或 MagicDNS，真正的登录和权限仍然由 SSH 控制。
- **`~/.ssh/config` 是 Codex 发现远端主机的入口**：终端里 `ssh vmware-ubuntu-desktop` 能连通，Codex App 才能复用这个 Host。
- **Ubuntu 必须安装并登录 Codex CLI**：Codex App 连接远端后，需要在 Ubuntu 上启动 Codex 相关服务。

所以完整配置顺序可以压缩成一句话：

```text
先让 Mac 能 SSH 到 Ubuntu -> 再让 Ubuntu 能运行 codex -> 最后在 Codex App 里选择这个远端项目目录
```

## 准备工作

你需要准备：

- Mac 上已安装并登录 Codex App。
- Ubuntu 已安装 `openssh-server`。
- Mac 和 Ubuntu 已加入同一个 Tailscale 网络。
- Ubuntu 上可以安装并运行 Codex CLI。

如果你不用 Tailscale，也可以直接使用局域网 IP；但如果 Ubuntu 在 VMware NAT 网络里，或者你经常换网络，Tailscale 会省心很多。

## 1. 在 Tailscale 里确认 Ubuntu 在线

先确认 Mac 和 Ubuntu 都已经登录同一个 Tailscale 账号。进入 Tailscale 控制台的 Machines 页面，可以看到 Ubuntu 设备和 Mac 都在线。

<img
  src="/images/docs/daily/Snipaste_2026-06-30_13-33-40.png"
  alt="Tailscale Machines 页面里 Ubuntu 和 Mac 设备在线"
  className="my-6 rounded-lg border border-fd-border"
/>

在 Ubuntu 上查看自己的 Tailscale IP：

```bash
tailscale ip -4
tailscale status
```

你会得到类似这样的地址：

```txt
100.64.12.34
```

后面 SSH 配置里的 `HostName` 就可以写这个地址。也可以使用 MagicDNS，例如：

```txt
vmware-ubuntu-desktop.tailnet-name.ts.net
```

我的建议是：第一次配置时先用 `100.x` 地址，等全部跑通后再换 MagicDNS。

## 2. 在 Ubuntu 开启 SSH 服务

Ubuntu 上安装并启动 SSH：

```bash
sudo apt update
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
sudo systemctl status ssh
```

如果启用了防火墙，放行 SSH：

```bash
sudo ufw allow OpenSSH
sudo ufw status
```

在 Mac 上测试能不能连通 Ubuntu 的 Tailscale IP：

```bash
ssh yourusername@100.64.12.34
```

如果这一步连不上，先不要去调 Codex。Codex SSH 本质上也是走 OpenSSH，终端里 `ssh` 不通，Codex 也不会通。

## 3. 配置 SSH 免密登录

Codex App 连接 SSH Host 时最好使用密钥，不要依赖密码输入。Mac 上如果还没有 SSH key，可以先生成：

```bash
ssh-keygen -t ed25519 -C "codex@mac"
```

把公钥复制到 Ubuntu：

```bash
ssh-copy-id yourusername@100.64.12.34
```

再次测试：

```bash
ssh yourusername@100.64.12.34
```

如果这次不需要输入密码，说明免密登录已经成功。

## 4. 在 Mac 配置 SSH Host Alias

Codex App 会读取 Mac 上的 `~/.ssh/config`，并从里面发现明确写出的 SSH Host。建议给 Ubuntu 写一个简单、稳定的别名。

编辑 Mac 上的 `~/.ssh/config`：

```text
Host vmware-ubuntu-desktop
  HostName 100.64.12.34
  User yourusername
  Port 22
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
  ServerAliveInterval 60
  ServerAliveCountMax 3
```

然后测试 alias：

```bash
ssh vmware-ubuntu-desktop
```

只要这条命令能进入 Ubuntu，Codex App 后面就可以复用同一个 SSH 配置。

注意两点：

- `Host` 要写具体名字，比如 `vmware-ubuntu-desktop`，不要只写 `Host *`。
- `IdentityFile` 要指向 Mac 上真实存在的私钥文件。

## 5. 在 Ubuntu 安装 Codex CLI

Codex App 连接 SSH Host 后，会通过 SSH 在远端启动 Codex 需要的服务。也就是说，Ubuntu 里必须能找到 `codex` 命令。

在 Ubuntu 上安装依赖和 Codex CLI：

```bash
sudo apt update
sudo apt install -y ca-certificates curl git
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

确认命令可用：

```bash
which codex
codex --version
```

如果提示找不到 `codex`，通常是 PATH 问题。可以把常见安装目录加入 shell 配置：

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

也建议跑一次诊断：

```bash
codex doctor
```

## 6. 在 ChatGPT 网站开启 Codex CLI 设备码登录

Ubuntu 如果是远端环境，普通浏览器回调登录经常不方便。更稳的方式是使用 device code 登录。

这里有一个很容易弄错的点：**设备码登录的开关不是在 Codex App 里配置，也不是在 Ubuntu 终端里配置，而是在 ChatGPT 网站里配置**。

先用 Mac 浏览器打开 ChatGPT 网站，进入 ChatGPT 的设置页面，开启 Codex CLI 的 device code authorization：

<img
  src="/images/docs/daily/Snipaste_2026-06-30_12-57-43.png"
  alt="ChatGPT 设置中开启 Codex CLI device code authorization"
  className="my-6 rounded-lg border border-fd-border"
/>

路径大致是：

```text
ChatGPT Settings
  -> Security and login
  -> Enable device code authorization for Codex
```

如果你使用的是团队或企业工作区，这个开关可能需要工作区管理员在权限设置里开启。总之这一步的配置入口在 **ChatGPT 网站 / ChatGPT 工作区设置**，不是 Codex App 的 `Settings -> Connections`。

确认 ChatGPT 网站里的开关已经打开后，再回到 Ubuntu 终端执行：

```bash
codex login --device-auth
```

终端会给出一个链接和一次性 code。用 Mac 浏览器打开链接，登录同一个 ChatGPT 账号，然后输入 code 完成授权。

完成后再验证：

```bash
codex doctor
```

如果这里登录成功，Codex App 通过 SSH 连接 Ubuntu 时，就能在远端正常启动 Codex。

## 7. 在 Codex App 添加 SSH 连接

回到 Mac 的 Codex App，进入：

```text
Settings -> Connections -> SSH
```

你应该能看到刚才在 `~/.ssh/config` 里配置的 SSH Host。截图里我的连接名是 `vmware-ubuntu-desktop`，端口是 `22`，身份文件是 `~/.ssh/id_ed25519`。

<img
  src="/images/docs/daily/Snipaste_2026-06-30_13-03-46.png"
  alt="Codex App Settings Connections SSH 页面"
  className="my-6 rounded-lg border border-fd-border"
/>

这里重点看几项：

- `主机`：对应 `Host vmware-ubuntu-desktop`。
- `端口`：默认 SSH 端口是 `22`。
- `身份文件`：对应 `IdentityFile ~/.ssh/id_ed25519`。
- `允许连接`：需要开启。

如果这里没有出现你的 Host，先回终端确认：

```bash
ssh vmware-ubuntu-desktop
```

终端能连，Codex App 才有继续排查的意义。

## 8. 创建远程项目

SSH 连接启用后，就可以在 Codex App 里创建远程项目。

创建项目时选择 **远程**，也就是选择已连接计算机上的文件夹：

<img
  src="/images/docs/daily/Snipaste_2026-06-30_13-13-47.png"
  alt="Codex App 创建项目时选择远程项目"
  className="my-6 rounded-lg border border-fd-border"
/>

接下来选择 Ubuntu 上的项目目录，例如：

```text
/home/yourusername/projects/my-app
```

进入项目后，Codex 执行命令、读写文件、安装依赖、跑测试，都会发生在 Ubuntu 环境里，而不是 Mac 本机。

## 快速自检清单

如果连接失败，按这个顺序查：

```bash
# Ubuntu 上确认 SSH 正常
sudo systemctl status ssh

# Ubuntu 上确认 Tailscale 在线
tailscale status
tailscale ip -4

# Mac 上确认 Tailscale 网络可达
ping 100.64.12.34

# Mac 上确认 SSH alias 可用
ssh vmware-ubuntu-desktop

# Ubuntu 上确认 Codex 可用
which codex
codex --version
codex doctor
```

## 常见问题

### Codex App 找不到 SSH Host

先确认 Mac 上 `~/.ssh/config` 有明确的 Host：

```text
Host vmware-ubuntu-desktop
  HostName 100.64.12.34
  User yourusername
  IdentityFile ~/.ssh/id_ed25519
```

然后确认终端能连：

```bash
ssh vmware-ubuntu-desktop
```

如果 `ssh` 命令都失败，优先修 SSH，不要先改 Codex。

### Codex App 连接后提示找不到 codex

这是 Ubuntu 登录 shell 的 PATH 问题。SSH 进入 Ubuntu 后执行：

```bash
which codex
echo $PATH
```

如果找不到，把 Codex 安装目录写入 `~/.bashrc` 或 `~/.profile`：

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

### 远端登录 Codex 卡住

优先使用 device code，但要先确认你已经在 **ChatGPT 网站** 里打开了 Codex CLI 的 device code authorization：

```bash
codex login --device-auth
```

如果只在 Ubuntu 里反复执行这条命令，但 ChatGPT 网站里的开关没有打开，登录流程仍然可能回退到普通浏览器登录或直接卡住。

### Tailscale IP 变不变

Tailscale 的 `100.x` 地址通常比 VMware NAT IP 稳定得多。你也可以在 Tailscale 管理台启用 MagicDNS，然后把 `HostName` 写成设备名。

## 使用建议

- 给 Ubuntu 使用普通用户，不要直接用 `root` 做日常开发。
- 项目尽量放在 Ubuntu 自己的 ext4 文件系统里，不要依赖 VMware 共享目录。
- SSH 用密钥登录，少用密码登录。
- 如果 Ubuntu 长期作为开发机，可以在 Tailscale 管理台按需关闭 key expiry。
- Codex App 只是入口，真正的依赖安装、构建和测试都发生在 Ubuntu 上，所以 Ubuntu 的 Node、Git、包管理器环境要配完整。
