> 整理一份包含前后端完整的项目基础架构，以后开发新项目可以统一用这个目录架构基础和技术栈去快速开发

目的：
- 避免每次创建新项目，AI创建的项目架构和技术栈都不一样，维护成本高；
- 后续完善后，可以打包成 skill，后续通过加载 skill 快速搭建项目；
- 培养 AI 开发习惯，让项目目录架构和技术栈尽量统一（方便维护和阅读）；

### 项目模板
```
coding-projects/
├── frontend/                          # 前端项目模板
│   ├── nextjs-template/
│   ├── reactjs-template/
│   ├── vue3-template/
│   └── react-native-template/
│
├── backend/                           # 后端项目模板
│   ├── express-template/
│   ├── nodejs-template/
│   ├── nestjs-template/
```

### 前端模板

#### Next.js 模板项目结构

```text
nextjs-template/
├── src/
│   ├── app/                           # App Router 路由、布局、错误边界
│   │   ├── page.tsx                   # 根路径入口，重定向到默认语言
│   │   ├── layout.tsx                 # 根布局
│   │   └── [locale]/                  # 多语言业务路由，中文 /zh，英文 /en
│   ├── components/
│   │   ├── common/                    # 基础组件和通用交互入口
│   │   ├── layout/                    # 应用壳、页面布局
│   │   └── feature/                   # 业务功能组件
│   ├── providers/                     # 应用级或功能级 Provider
│   ├── services/api/                  # Axios 客户端、API 模块、错误模型、Token 工具
│   ├── store/                         # Zustand 跨页面客户端状态
│   ├── hooks/                         # React Hook 和业务逻辑复用
│   ├── i18n/                          # next-intl 配置、路由、语言包
│   ├── theme/                         # 主题变量和运行时切换
│   ├── config/                        # 环境变量解析和应用配置
│   ├── types/                         # API 类型和业务实体类型
│   ├── utils/                         # 纯函数工具
│   ├── styles/                        # 全局样式
│   ├── test/                          # Vitest / Testing Library setup
│   └── proxy.ts                       # next-intl 请求中间件
├── tests/
│   ├── unit/                          # 跨模块单元测试
│   ├── integration/                   # 集成测试
│   └── e2e/                           # 端到端测试
├── public/                            # 静态资源
├── next.config.mjs
├── vitest.config.ts
├── eslint.config.mjs
├── package.json
├── README.md
├── GUIDE.md
├── TEST.md
├── MERMAID.md
├── AGENTS.md
└── CLAUDE.md
```
