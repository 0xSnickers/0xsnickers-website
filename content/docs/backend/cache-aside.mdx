## 文章核心内容

Cache Aside 是常见的旁路缓存模式：读请求先查缓存，未命中再读数据库并回填。它适合允许短暂缓存延迟、读多写少的业务数据。

- 数据库保存业务数据。
- 缓存设置有限的存活时间。
- 更新数据库后删除对应缓存。

## 使用方式

先确定缓存 key、过期时间和允许的数据延迟。不要把认证凭证、未提交事务的结果或跨用户的私有结果混用同一个 key。

## 怎么实现

### 1. 读取并回填

下面是伪代码，cache 和 db 表示应用已有的访问封装：

```ts
async function getUser(id: string) {
  const key = `user:${id}`;
  const cached = await cache.get(key);
  if (cached !== null) return JSON.parse(cached);

  const user = await db.findUser(id);
  if (user !== null) {
    await cache.set(key, JSON.stringify(user), { ttlSeconds: 300 });
  }
  return user;
}
```

### 2. 写入后失效缓存

数据库事务提交成功后，再删除对应 key。删除失败应重试或通过可靠事件补偿；过期时间用于限制旧值保留时间。

### 3. 控制集中回源

热点 key 可以用请求合并避免并发重建。为过期时间增加随机偏移，可减少大量 key 同时过期。

## 常见问题

### 先更新数据库再删缓存，是否绝对一致

并发读取可能在删除后把旧值重新写入缓存。这种方案仍属于最终一致性设计。需要更强一致性时，应评估版本号校验、可靠变更事件或直接读取数据库。

### 缓存故障是否影响接口

根据业务设计超时和降级策略，并限制回源并发，避免故障时所有请求集中压向数据库。
