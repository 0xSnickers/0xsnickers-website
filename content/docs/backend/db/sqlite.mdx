## 文章核心内容

SQLite 是嵌入式关系型数据库，数据通常存储在单个文件中，无需独立数据库服务。它适合本地应用、脚本、小型服务和开发工具，应用通过库直接读写文件。

- 部署简单，连接目标是文件路径。
- 支持 SQL、索引和事务。
- 多个连接可以读取，写入需要协调。

## 使用方式

先安装 sqlite3 命令行工具，并确认目标目录可写。打开数据库时，文件不存在就会创建：

```bash
sqlite3 notes.db
```

应用部署时使用稳定的绝对路径，并把数据库放在可持久保存的磁盘上。

## 怎么实现

### 1. 开启外键并建表

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  email TEXT NOT NULL UNIQUE,
  name TEXT NOT NULL
);
```

外键检查需要在每个连接上启用。INTEGER PRIMARY KEY 可以在插入时自动生成整数 ID。

### 2. 查询并使用事务

```sql
BEGIN;
INSERT INTO users (email, name) VALUES ('alice@example.com', 'Alice');
UPDATE users SET name = 'Alice Chen' WHERE email = 'alice@example.com';
COMMIT;

SELECT id, name FROM users ORDER BY id LIMIT 20;
```

业务代码使用参数绑定，失败时回滚。

### 3. 配置并发和备份

```sql
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
```

WAL 改善读写并发，仍然同一时刻只有一个写事务。busy_timeout 给当前连接设置锁等待时间，长事务仍应尽量缩短。

在 sqlite3 命令行中可以使用在线备份命令：

```text
.backup notes-backup.db
```

> WAL 模式运行中可能存在 -wal 和 -shm 文件。使用备份 API 或命令生成一致快照。

## 常见问题

### database is locked

通常有其他连接持有写锁。缩短写事务、配置锁等待，并将高并发写入任务排队处理。

### 重启后数据丢失

检查是否使用了 :memory:、临时目录或容器的临时文件系统，并确认不同进程连接的是同一文件路径。
